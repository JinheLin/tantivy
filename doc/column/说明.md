# 专栏工作区说明（doc/column）

这是一套“边读源码边写专栏”的工作区：每篇文章一个 Markdown 文件，配套统一模板与 TODO，确保产出可复现、可迭代。

## 目录结构

- `doc/column/文章模板.md`：单篇文章模板（复制后改标题即可）
- `doc/column/第*部分-*/??-*.md`：文章草稿（按 Part 目录 + 编号命名）
- `doc/column_outline.md`：总大纲与进度表（勾选/状态更新）

## 写作约定（建议坚持）

- 每篇文章目标是“回答一个主问题”，不要在一篇里塞太多主题。
- 读代码“按调用链”：从 example/或公开 API 入口出发，逐层下钻。
- 每篇至少做 1 个实验并给出“验证点”（例如：输出包含哪些行/段数变化/查询命中数变化）。
- 代码引用尽量写清楚：
  - `路径 + 关键符号名`（比行号更稳定）
  - 必要时附带“在哪个模块里 re-export”帮助读者定位

## 常用命令（本地）

- 跑示例：`cargo run --example basic_search`
- 跑库与 tests：`cargo test --tests --lib`（也可 `make test`）
- 格式化：`make fmt`（需要 nightly）

## 发布前检查清单（每篇）

- [ ] 文章“主问题”一句话能说清楚
- [ ] 有可复现实验 + 读者能验证的输出/现象
- [ ] 关键入口文件清单齐全（按阅读顺序）
- [ ] 图或表至少 1 个（结构图/数据流/状态机/文件布局）
- [ ] FAQ ≤ 5 条，覆盖最常见疑问
